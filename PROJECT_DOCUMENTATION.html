Overview — what this is & why

A reusable React + Three.js framework for building sites where the webpage is a WebGL world, not a webpage with a 3D widget bolted on.

Standard websites are flat. Active Theory (activetheory.net) proved that WebGL-powered navigation produces memorable, immersive experiences — but their approach uses a proprietary engine (Hydra) that isn't reusable. webgl-frontend rebuilds that same quality of experience on an open, extensible stack: Three.js via React Three Fiber, custom GLSL shaders on every surface, a scroll-driven camera that lerps between 3D "rooms," and a mandatory post-processing pass (bloom, chromatic aberration, vignette).

The central architectural idea is a clean split between two layers that share one coordinate system: a full-viewport <canvas> at z-index: 0 renders the 3D world, and a DOM overlay at z-index: 10+ floats navigation, labels, and HUD above it. A small set of Zustand stores is the single bridge between the two — they share currentScene, scrollProgress, mouse, and time, and both layers subscribe to slices of that state.

Key concept — "the webpage lives inside a WebGL world"
Every visible surface is a hand-written ShaderMaterial. Built-in materials (MeshStandardMaterial, MeshPhongMaterial, etc.) are banned — they produce the generic "looks like Three.js" appearance. The Active Theory aesthetic only exists when you control every pixel via custom GLSL. This is the single most important rule of the project.
Watch out — this is a scaffold, not a running app yet
As of v0.2.0, the infrastructure is complete (Docker, CI, config, docs, agent tooling) but the 3D code is not implemented. src/ currently contains only the Canvas shell (App.tsx), the entry point (main.tsx), and three type stub files. No rooms, shaders, hooks, stores, navigation, or post-processing exist yet. Everything in CLAUDE.md's directory tree under components/, hooks/, stores/, and shaders/ is planned, not built. This document distinguishes built vs. planned at every step.

This is one of Amram's personal projects, treated with production rigor. It is phased across three milestones (core framework → content integration → performance/mobile), currently at the very start of Phase 1. The authoritative references are docs/WEBGL_FRONTEND_MASTER_PLAN.md (the master plan) and webgl-immersive-integration-prompt.md (an 832-line design spec with full shader techniques and reference room implementations).

Architecture

Two layers, one coordinate system, one shared store. The canvas renders the 3D world; the DOM renders UI; Zustand is the only bridge between them.

Layer model

The whole site is a single full-viewport <canvas>, fixed-position, at z-index: 0. HTML UI (navigation dots, labels, HUD) floats above it at z-index: 10+, with pointer-events: none on the overlay container and pointer-events: auto only on actually-interactive elements. This layering is already encoded in src/App.tsx, even though the contents of each layer are empty.

Rooms in world space

Rooms are <group> nodes placed at fixed intervals along the Y axis. The camera target for room N is y = -ROOM_SPACING * N, with ROOM_SPACING = 30 units (large enough to prevent visual bleed between adjacent rooms). A room receives an active boolean and only updates its shader uniforms when active or adjacent — distant rooms freeze.

The render loop

One R3F render loop drives everything — there is no separate loop for UI vs GL. Each frame: update inputs → lerp mouse toward target → lerp camera toward the active room → update active/adjacent room uniforms → render scene to a texture → bloom → chromatic aberration → vignette → output to screen.

Navigation sequence

Key concept — frame-rate-independent camera damping
The camera never snaps. It sets a target and closes the gap each frame with an exponential lerp: lerpFactor = 1 - Math.pow(0.04, delta). A flat lerp factor (e.g. 0.05) looks different at 30fps vs 144fps; the exponential form gives identical visual motion at any frame rate. Never set camera.position directly — always set a target and let the lerp run.

Core modules & components

The pieces that exist today, drilled down, plus the planned modules with their exact target files and intended logic so you know precisely what to build next.

App shell src/App.tsx

The only rendering component that exists. It establishes the two-layer architecture: an R3F Canvas at z-index: 0 and an empty DOM overlay at z-index: 10. The Canvas is configured with the camera and renderer settings the rest of the framework depends on.

Notable settings: dpr={[1, 2]} caps the device pixel ratio at 2.0 (the mandated optimization); alpha: false gives an opaque canvas (black background from index.html); the camera matches the design spec (fov 60, near 0.1, far 500, start at z=8). The overlay div uses pointerEvents: 'none' so the canvas remains interactive beneath it.

First implementation step
Replace the {/* Experience component will be added here */} comment with <Experience /> once that component exists, and put <NavigationDots /> in the overlay div. Those two insertions wire the whole framework together.
src/App.tsxTwo-layer root. The integration point for Experience + DOM overlays.
src/main.tsxMounts App in StrictMode.
Type contracts src/types/

BaseUniforms is the minimum-uniform contract from the master plan: every shader receives uTime, uMouse, uResolution, and uProgress (the latter reserved for Phase-2 transitions). Per-room interfaces extend it with their specific uniforms.

PostProcessing planned · src/components/three/PostProcessing.tsx

Not built yet. Planned as an <EffectComposer> from @react-three/postprocessing with three passes: UnrealBloom (strength 0.8, radius 0.4, threshold 0.85), then a custom vignette + chromatic aberration shader pass. Post-processing is mandatory, not optional — it's what takes the look from "three.js" to "Active Theory." The vignette/chromatic fragment logic offsets the R and B channels along the screen vector and darkens edges via smoothstep on distance-from-center.

Room 0 — Nebula Field planned · src/components/three/NebulaRoom.tsx + nebula.vert/.frag

Not built yet. A THREE.Points cloud (4000–8000 particles in a sphere) with per-particle aRandom/aSize attributes, additive blending, and depthWrite: false. The vertex shader displaces particles with 3D simplex noise and pushes them away from the mouse; the fragment shader draws soft circles and mixes two colors by the per-particle random.

Room 1 — Grid Horizon planned · src/components/three/GridRoom.tsx + grid.vert/.frag

Not built yet. A wireframe PlaneGeometry(20, 20, 80, 80) rotated ~45° on X. The vertex shader sums two octaves of simplex noise for terrain elevation and adds a mouse-driven ripple wave; the fragment shader maps color to elevation and fades the edges by UV distance.

Room 2 — Crystal Lattice planned · src/components/three/CrystalRoom.tsx + crystal.vert/.frag

Not built yet. An InstancedBufferGeometry over IcosahedronGeometry(0.15, 0) with 200–400 instances, per-instance aOffset/aSeed. The vertex shader applies per-instance rotation + orbital motion and computes a fresnel term; the fragment shader mixes two colors by seed and drives alpha from fresnel — a floating field of crystals with glowing edges. One draw call for all instances.

Navigation hooks & dots planned · src/hooks/ + src/components/ui/

Not built yet. useScrollNavigation.ts binds wheel (with a cooldown to prevent rapid-fire), arrow keys + spacebar, and basic touch swipe, clamping the result to [0, sceneCount-1] and calling goToScene. useMouseTracking.ts normalizes pointer coords to −1…1 and lerps them. NavigationDots.tsx (DOM overlay) reflects the current scene and allows click-to-jump.

Zustand stores planned · src/stores/navigationStore.ts + inputStore.ts

Not built yet. Two stores form the cross-layer bridge. navigationStore holds currentScene, targetScene, transitioning, sceneCount, and a goToScene(index) action. inputStore holds mouse, mouseTarget, scrollProgress, and time. The store shapes are specified verbatim in CLAUDE.md §2.

Do not put Three.js objects in the stores
Never store geometries, materials, textures, meshes, cameras, or scenes in Zustand or React state. They are mutable class instances — storing them causes serialization issues and needless re-renders. Use useRef for all mutable Three.js objects. Only primitives, plain objects, and arrays of primitives belong in the stores.
Shared GLSL library planned · src/shaders/includes/noise.glsl

Not built yet. The Ashima Arts / Stefan Gustavson 3D simplex noise (snoise(vec3)) goes here, imported via vite-plugin-glsl's #include into every shader that needs organic motion. The full implementation is reproduced in the design spec §10 — copy it verbatim. Every room's vertex shader depends on it.

Key concept — additive blending = glow
Set blending: THREE.AdditiveBlending and depthWrite: false. Colors add instead of replacing: dark pixels become transparent, bright pixels stack into glow. This is the foundation of the nebula and crystal looks, and it composes with the bloom pass.

How to run it

Local dev via Vite, or containerized via the launcher scripts. Both serve on port 5240.

Local dev (Vite, hot reload)

  1. Install deps: pnpm install.
  2. Start the dev server: pnpm dev.
  3. Open http://localhost:5240. Today you'll see a black full-viewport canvas (no 3D content yet).

Other scripts from package.json: pnpm lint (ESLint), pnpm test (Vitest run), pnpm test:watch, pnpm test:coverage, pnpm build (tsc -b && vite build), pnpm preview.

Docker (production-like, nginx)

  1. macOS/Linux: run run_webgl_frontend.sh. Windows: run run_webgl_frontend.bat.
  2. The script runs docker compose up --build -d, waits for the frontend to respond, and opens the browser at http://localhost:5240.
  3. At the prompt, pick a control: [k] stop/keep image · [q] stop/remove image · [v] full cleanup (images + volumes) · [r] full restart (down → rebuild → relaunch).
Windows + PyCharm gotcha (from Amram's workflow memory)
The .bat launcher's menu uses set /p, which needs a real terminal. Right-click → Run in PyCharm is a non-TTY batch run-config where set /p hangs and output buffers. Run the .bat from the Terminal tab (or enable "Emulate terminal in output console") rather than patching the script.
Agent-teams launchers
claude-teams.sh / claude-teams.bat just export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 and exec claude. They have nothing to do with running the app — they launch Claude Code with the experimental agent-teams flag.

How to edit & extend it

Practical, owner-focused recipes. Since the 3D code is unbuilt, the highest-leverage "edits" are the Phase 1 build steps themselves — in dependency order.

The recommended Phase 1 build order

  1. Create src/stores/navigationStore.ts and src/stores/inputStore.ts (Zustand). Shapes are in CLAUDE.md §2. Test these first — pure logic, easy 100% coverage.
  2. Add src/components/three/Experience.tsx and drop <Experience /> into src/App.tsx (replacing the placeholder comment).
  3. Add src/components/three/CameraRig.tsx with the exponential lerp reading targetScene.
  4. Add src/hooks/useScrollNavigation.ts + src/hooks/useMouseTracking.ts and wire them in Experience / App.
  5. Add src/shaders/includes/noise.glsl (copy snoise verbatim from the design spec §10).
  6. Build Nebula Room first end-to-end (component + nebula.vert + nebula.frag) — particles are the most forgiving start.
  7. Add src/components/three/PostProcessing.tsx (bloom + vignette/chromatic). Even bloom alone transforms the look.
  8. Build Grid Room, then Crystal Room.
  9. Add src/components/ui/NavigationDots.tsx in the DOM overlay div.
  10. Add resize handling that updates renderer, camera aspect, and uResolution uniforms.

To add a new room

  1. Create src/components/three/<Name>Room.tsx implementing RoomProps from src/types/RoomConfig.ts. Position its <group> at y = -index * spacing.
  2. Create src/shaders/<name>.vert and <name>.frag (never inline GLSL). Import shared noise from includes/noise.glsl.
  3. Add a <Name>Uniforms interface to src/types/ShaderUniforms.ts extending BaseUniforms.
  4. Register the room in Experience.tsx and bump sceneCount in the navigation store.
  5. Update uniforms only when active or adjacent; dispose geometry/material on unmount.
Do not break these invariants
No built-in materials (ShaderMaterial only). No inline GLSL strings. No Three.js objects in Zustand/React state — use refs. Dispose every geometry/material/texture you create on unmount. These are enforced by the frontend-protocol skill and the post-tool-use.cjs hook, which injects a reminder whenever you edit a file under shaders/, components/three/, or stores/.

After any change

Per CLAUDE.md §9: update docs/status.md and docs/versions.md, compute the next semver yourself, and do not edit package.json's version directly (the release workflow owns that). Git is hands-off — the owner commits.

Testing

Vitest + React Testing Library, jsdom environment. The harness is wired; no test files exist yet.

tests/setup.tsImports cleanup from RTL and calls it in afterEach — Vitest does NOT auto-cleanup like Jest. Also imports @testing-library/jest-dom.

What to test (per CLAUDE.md §5): store logic (navigation transitions, input updates), hook logic (scroll index clamping, mouse normalization), JS utility helpers (lerp/clamp/smoothstep), and component rendering (rooms mount without crashing, dots reflect state). What not to mock: WebGL context, shader compilation, Three.js math — test against real computations. Use expect(value).toBeCloseTo(expected, precision) for floats, never exact equality.

Coverage
The global target is 100%, enforced in CI. src/types/**, src/shaders/**, and src/main.tsx are excluded from coverage (declarations, GLSL, and the bootstrap entry are not unit-testable). Tests live in tests/ and match tests/**/*.test.{ts,tsx}.

Build, CI & deployment

CI is GitHub Actions (not GitLab, despite CLAUDE.md §7's heading). Two workflows: a four-stage CI pipeline and a manual release/version-bump.

CI pipeline

Defined in .github/workflows/ci.yml. Triggers on push/PR to main, staging, dev (and manual dispatch), with in-progress cancellation. Stages run sequentially via needs:

StageCommandGate
lintpnpm lintFails on any ESLint error.
testpnpm test -- --coverage (+ junit report)Needs lint. Fails on test failure / coverage gap.
buildpnpm build, upload dist/ artifactNeeds test. Must compile.
docker-builddocker/build-push-action (no push, GHA cache)Needs build. Only on main/staging.

Release / versioning

.github/workflows/release.yml is a manual workflow_dispatch with a bump choice (patch/minor/major). On main, it runs pnpm version, commits the bumped package.json + lockfile, tags, and pushes. This is the only thing that should edit the version field — never bump it by hand.

Docker image

Dockerfile is a two-stage build: stage 1 (node:20-alpine) enables pnpm via corepack, installs with --frozen-lockfile, and runs pnpm build; stage 2 (nginx:alpine) copies nginx.conf and the built dist/, exposes :80, and runs nginx. The nginx config does SPA fallthrough to index.html and caches/gzips assets including .glsl/.vert/.frag.

Doc drift — CLAUDE.md says GitLab
CLAUDE.md §7 and the directory tree reference .gitlab-ci.yml and a .claude/ dir. Neither exists. The real CI is GitHub Actions under .github/workflows/, and the agent wiring is in .codex/ + .agents/. Trust the files, not the prose.

Domain glossary

Terms a newcomer needs to navigate the codebase and the design spec.

Room / scene
A distinct 3D environment with its own geometry, shaders, and interactivity, placed at a fixed Y offset. The camera lerps between rooms.
R3F (React Three Fiber)
A React renderer for Three.js. Lets you express a 3D scene as JSX components; useFrame runs per-frame, useThree accesses renderer/camera/scene.
ShaderMaterial
A Three.js material driven by hand-written GLSL vertex + fragment shaders. The only material type allowed here.
Uniform
A value passed from JS into a shader, constant across a draw call (e.g. uTime, uMouse). The JS→GPU bridge, updated each frame.
Exponential lerp
Frame-rate-independent damping: 1 - pow(decay, dt). Produces identical motion regardless of frame rate.
Simplex noise
A gradient noise function (snoise) for organic, cloud-like randomness — drives particle displacement, terrain, surface distortion.
Fresnel
Edge glow based on view angle: pow(1 - abs(dot(view, normal)), e). Produces rim lighting and the crystal/glass look.
Additive blending
A blend mode where colors add instead of replacing. Dark→transparent, bright→glow. Paired with depthWrite: false.
Post-processing
Rendering the scene to a texture, then running shader passes (bloom, chromatic aberration, vignette) before display. Done via EffectComposer.
Bloom
A glow effect that bleeds bright pixels into neighbors. Tuned by strength / radius / threshold.
Chromatic aberration
Offsetting the R and B channels to simulate lens color fringing.
InstancedBufferGeometry
One geometry drawn many times in a single draw call, with per-instance attributes. Used for the crystal field.
ROOM_SPACING
The world-space Y gap between rooms (30 units).
Active Theory
The creative studio whose immersive-WebGL aesthetic this framework targets.
